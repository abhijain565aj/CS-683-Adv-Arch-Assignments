\section{Task 2C: Software Prefetching + SIMD}

\subsection{Combined Implementation}
In the combined implementation (\texttt{matmul\_optimized.cpp}), the matrix multiplication is cache-blocked into $BM=32$ and $BN=32$ tiles. Within each tile, a $2 \times 4$ register-blocked micro-kernel uses 256-bit AVX2 intrinsics (\texttt{\_\_m256}) and \texttt{\_mm256\_fmadd\_ps}. The submitted final kernel uses a fixed prefetch distance of 64 floats and issues \texttt{\_mm\_prefetch} only for upcoming $A$ data. The active $B$ rows are reused across output rows by the loop structure and rely on normal cache and hardware-prefetch behavior.

\subsection{Experimental Setup}
\begin{itemize}
    \item \textbf{Matrix dimensions:} $128 \times 128$ up to $2048 \times 2048$
    \item \textbf{SIMD Widths:} 128-bit, 256-bit (AVX2)
    \item \textbf{Prefetch distances:} 16, 32, 64, 128, 256, 512 floats
    \item \textbf{Cache fill levels:} T0, T1, T2, NTA
    \item \textbf{Primary Dataset:} Hardware prefetcher enabled (ON)
\end{itemize}

\subsection{Analysis}

\subsubsection{SIMD Width and Instruction Count}
Moving from scalar code to 128-bit and then 256-bit SIMD reduces the number of executed instructions. A 256-bit vector instruction processes 8 floats, but the results do not by themselves establish a single memory-bandwidth bottleneck. They suggest that, after vectorization, data delivery becomes a larger fraction of execution time.

\subsubsection{Prefetch Cache Fill Level}
In this sweep, \texttt{T0} produced the best combined result for most sizes. This differs from the best geometric-mean hint in Task 2A. Prefetch locality hints are requests rather than guarantees of cache placement, so the difference should be read as a workload-specific measurement, not as proof that SIMD data must arrive in L1.

\subsubsection{Prefetch Distance and Cache Metrics}
Across the sweep, 32 floats was the best global prefetch distance by geometric mean. This does not imply that it is best at every size: the per-size best configurations in Table~1 include other distances. Large distances can add cache pressure, but if the distance is at least $K$, the guarded prefetch does not execute and the point instead represents an effectively no-prefetch case.

\subsection{Task 2 Conclusion}
The parameter sweep shows that software prefetching alone reached about $2.08\times$ speedup, SIMD reached about $12.6\times$, and their best per-size sweep configuration reached $17.11\times$. The later fixed, hand-tuned kernel evaluated by the autograder is a separate result: as reported in the appendix, it reached $22.07\times$ on the primary machine at $N=1024$. The two numbers use different configurations and should not be treated as contradictory. Overall, the results show that vectorization, register blocking, locality, and prefetch tuning can combine effectively, while the best setting remains workload- and machine-dependent.
