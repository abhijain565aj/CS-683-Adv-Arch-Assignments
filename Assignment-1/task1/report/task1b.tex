\section{Task 1B: Tiling}

\subsection{Baseline Profiling}
Profiling the baseline (naive) 2D convolution yields an L1-D MPKI of 0.06 for a $2048 \times 2048$ matrix with a kernel size of 5. We do not use the 448 KiB aggregate cache-summary value as a per-core L1-D capacity: tile behavior depends on the effective private-cache capacity available to the executing core and on the complete active working set.

\subsection{Implementation}
The tiled 2D convolution is implemented by dividing the output matrix into square blocks of a fixed dimension, \texttt{sz} . The outer loops iterate over the tile origins (\texttt{oyT} and \texttt{oxT}) to process the image block by block . Within each tile block, the output values are initialized to zero, and the kernel loops (\texttt{ky} and \texttt{kx}) accumulate the weighted inputs strictly within the local spatial bounds . This reorders the memory accesses to keep the active working set confined within the cache.

\subsection{Analysis}

\begin{enumerate}
    \item \textbf{Report the changes in L1-D MPKI observed when moving from naive to tiled 2D convolution. Justify your observations.} \\
    The L1-D MPKI increased significantly, jumping from just 0.06 in the naive version to a range of $\sim$6 to 19 in the tiled version. The naive implementation accesses memory in long, predictable linear streams, which hardware prefetchers can easily identify and hide. Tiling breaks these accesses into short, discontinuous blocks, which disrupts the hardware prefetchers and exposes the actual cache miss rate.
    
    \item \textbf{How did L1-D MPKI vary across different matrix sizes and tile sizes? Explain your findings in terms of the cache hierarchy and working set sizes.} \\
    MPKI reaches a minimum at intermediate tile sizes (for example, 128 for a $2048 \times 2048$ matrix). A convolution tile requires an output tile, the corresponding input region including its halo, and kernel data; the loop order also affects which portions coexist. As tiles become large, this active working set increasingly exceeds effective private-cache capacity and locality declines. Very small tiles add loop and boundary overhead without enough additional reuse to offset it.
    
    \item \textbf{Did you achieve a speedup? If yes, quantify the improvement and identify the contributing factors. If not, analyze the limiting factors and propose possible solutions.} \\
    Yes, a speedup was achieved. For a $2048 \times 2048$ matrix, the speedup reached $\sim$1.27$\times$ at a tile size of 1024, and peaked at 1.53$\times$ for a $512 \times 512$ matrix with a tile size of 256. Although the tiled runs show a higher L1-D MPKI, execution time improved at these points. The result is consistent with improved temporal locality: reused data are more likely to be served from the cache hierarchy rather than lower levels of memory.
\end{enumerate}
